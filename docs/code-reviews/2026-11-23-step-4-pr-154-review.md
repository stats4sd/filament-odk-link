## Findings fixed

### 1. Submission ingestion ran before integration config was validated (correctness)

`ProcessOdkSubmission::handle()` ran `OdkLinkService::processSubmission()` first and only then rejected a populated legacy `submission.process_method` / `foreign_key_process_method` or an invalid `contracts.submission_processor`. Ingestion is not idempotent: `processRootSection()` calls `Entity::create()` on every run. A host upgrading with an old published config would therefore ingest, fail, and create duplicate entities and values on each retry.

Fix: validate the legacy settings and resolve the processor before ingestion. The processor still runs only after successful ingestion, and processor runtime failures still propagate. The test that asserted "ingest, then reject" now asserts that no ingestion happens; a new test covers an invalid processor class.

### 2. Remaining host coupling in `MediaHasBeenAddedEvent` (boundary)

`src/Events/MediaHasBeenAddedEvent.php` still type-hinted `Stats4sd\FilamentTeamManagement\Models\User`, a class from a package that is not a dependency. PHPStan baseline entries hid it, and neither architecture rule caught it: the shipping-boundary prefix list didn't include that namespace, and the Pest `toUse` rule did not list `Events` or `Http`.

Fix: `importedBy` is now a nullable `Model&PlatformUser`; an implicit `auth()->user()` goes through `ConfiguredModels::validateUser()`. `Stats4sd\FilamentTeamManagement\` is banned in both architecture rules, `Events` and `Http` are covered by the namespace rule, and the two stale baseline entries are removed. Tests cover an explicit importer, the authenticated importer, and rejection of an incompatible logged-in user.

### 3. A pre-registry published config silently emptied the model registry (upgrade safety)

Laravel merges package config shallowly, so a host's published config from before this change replaces the whole `models` array and has no `registry` key. `ConfiguredModelRegistry` read that as `[]`, and `getModelByTablename()` silently returned `null` for package tables such as `countries`.

Fix: a missing key now raises the registry's descriptive configuration error and says to re-publish or copy the entries. An explicit empty array is still allowed.

## Not fixed: blocks merging

### PhpSpreadsheet 1.x is now marked deprecated, failing `phpstan` on every PR

CI's `phpstan` job installs with `dependency-versions: highest` and ignores the lockfile. A PhpSpreadsheet 1.x release published after 2026-11-16 (PR #166 passed then) marks the whole `Spreadsheet` class `@deprecated` ("migrate to release 5 or later"). With deprecation rules enabled, `src/Services/UpdateXlsformTitleInFile.php:20` fails analysis. The PR doesn't touch that code, and `dev` is affected equally. The real fix is moving to `maatwebsite/excel` 4 and PhpSpreadsheet 5 (Dependabot PR #160, which currently fails CI). The other option is a temporary baseline entry, which the package `CLAUDE.md` rules out without a decision. This needs an owner decision.

Running PHPStan locally against the committed lockfile gives different results from CI (unmatched baseline patterns for `GenerateSubmissions` and two widget `$view` properties). The lockfile lags "highest", so local `composer analyse` is not a reliable predictor of the CI result.

## Noted, no change

- The success-path notification (`OperationNotifications::send`) throws if a role resolver returns a non-`PlatformUser`, which fails the job after its work is done. The plan explicitly keeps success-transport failures as job failures for this step.
- `FilamentCurrentOwnerResolver` checks `getCurrentPanel()` rather than the old `getCurrentOrDefaultPanel()`. Tenants are only set by panel middleware, so outside a panel request both return no owner. The behaviour is equivalent in practice and stricter for non-tenant panels, which was a fix from the earlier review.
- Deployment failure bodies interpolate the ODK error message into `HtmlString` unescaped. This predates the PR, which correctly preserves it per the plan.
